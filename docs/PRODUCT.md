# CalendarMark 产品设计

## 1. 产品定位

CalendarMark 不是传统的任务日历，而是一张“时间地图”：用户在日期上留下轻量的标签、文字和图片，之后可以用月份视角重新看见自己的工作和生活轨迹。

核心体验是：**看到日期 → 快速标记 → 需要时补充上下文 → 回顾**。

## 2. MVP 用户故事

1. 我在 Windows 上按快捷键，就能把 CalendarMark 主窗口叫出来。
2. 我点击日历中的一天，右侧抽屉滑入，不需要离开当前月份。
3. 我可以输入标题、正文，点击快捷标签，也可以直接创建新标签。
4. 我可以添加图片、TXT、Markdown 或 PDF 作为当天的附件。
5. 我关闭窗口后应用仍在托盘，需要时可以从托盘重新打开或退出。
6. 我可以在设置中修改快捷键、主题、标签和 Notion 数据源配置。

## 3. 信息架构

```text
CalendarMark
├── 日历总览
│   ├── 月份切换
│   ├── 日期格子 / 标签 / 附件标记
│   ├── 本月概览
│   └── 最近更新
├── 日期记录抽屉
│   ├── 标题
│   ├── 内容
│   ├── 快捷标签
│   ├── 附件
│   └── 保存 / 删除
└── 设置
    ├── 数据源 / Notion

    ├── 界面
    └── 标签管理
```

## 4. 视觉和交互原则

- **像纸张一样安静**：米白画布、绿色主色、低对比边界，减少工具感。
- **信息密度可控**：日历格子只展示最多两个标签，其余用 `+N` 收起。
- **上下文不丢失**：日期编辑使用右侧抽屉，不跳转页面；抽屉关闭时保留月份和选中日期。
- **反馈要即时**：保存、删除、标签变更和 Notion 连接/同步结果均提供轻量 toast。
- **桌面优先、移动可用**：桌面使用侧边栏；窄屏时侧边栏收缩为图标，设置导航转为图标栏。

## 5. 关键交互

### 日期记录

- 点击任意日期打开抽屉。
- 没有记录时显示空白草稿；已有记录时加载该日期记录。
- 标题、正文、标签、附件任意一项有内容即可保存。
- 关闭按钮、遮罩、取消按钮都只关闭抽屉，不丢失已经保存的记录。
- 附件单个限制 5 MB；超过限制时不加入草稿。

### 托盘和快捷键

- Windows/macOS 启动后创建托盘图标。
- 托盘右键菜单包含：打开 CalendarMark、打开设置、退出。
- 窗口关闭事件被拦截并隐藏窗口，应用继续驻留托盘。
- 默认快捷键为 `CommandOrControl+Shift+Space`；设置改变后重新注册。

### Notion

数据源设置不把 Notion 写死为唯一选项，而是使用可替换的数据源选择器。当前提供：

- **Notion**：首个已实现的外部数据源，选中即远程直连——读取、保存、删除直接作用于当前数据集；支持数据集发现、添加/移除本机同步目标、数据集切换、连接检查、手动重新读取、页面归档和附件上传。
- **本地存储**：当前可用，适合离线记录；可在设置中对已配置的 Notion 数据集执行“拉取到本地 / 推送到 Notion”。
- **WebDAV / Obsidian Vault**：展示为规划中的数据源，暂不允许连接。

选择 Notion 后，页面内提供三步连接引导：创建 Internal connection 并复制 token、将目标数据库通过 Add connections 分享给连接、回到 CalendarMark 发现并添加数据集。Token 不应被截图或提交到版本库。

数据集管理是本机配置，不会删除远端内容。用户可以点击“发现数据集”读取当前 Token 已授权的 data source，点击“添加数据集”保存多个同步目标，再点击列表项切换当前目标；移除数据集只移除本机引用。

建议映射如下：

| CalendarMark | Notion 属性 | 类型 |
| --- | --- | --- |
| `date` | Date | date |
| `title` | Title | title |
| `content` | Content | rich_text |
| `tagIds` | Tags | multi_select |
| `attachments` | Attachments | files / URL |

CalendarMark 不在网页层直连 Notion，而是通过 Tauri IPC 将操作交给 Rust 适配器，避免把请求逻辑和令牌放进浏览器网络层。发现数据集时按 Token 搜索可访问的 data source，选定后读取 schema，再按属性类型建立映射；至少需要一个 `title` 和一个 `date` 属性。

数据源语义分为两种：选择 Notion 时为远程直连，应用启动、切换数据集或点击“重新读取”时查询远端页面，日历展示当前 Notion 数据，保存和删除直接写入远端，不落盘到本机 entries/tags 存储；选择本地存储时以本机记录为主，用户可在设置中显式点击“拉取到本地”或“推送到 Notion”。

推送规则：没有 `remote` 引用的本地记录创建 Notion 页面，已有引用的记录更新对应页面；本地附件通过 Notion File Upload API 上传到 `files` 属性。删除带远端引用的本地记录时，CalendarMark 会先将 Notion 页面移入回收站。

## 6. 非目标（MVP 不做）

- 多人协作、账户系统、CalendarMark 云端服务。
- 复杂任务管理、提醒、重复事件和全天事件语义。
- 在本地存储层直接保存大量原图或视频。
- Notion 双向同步的自动冲突合并、后台队列和离线重试。
